Gates, Combinators, and Turing and Kleene

One idea that occurred to Schönfinkel and was explored extensively by Curry and Feys is to get rid of the use of variables entirely. Instead focus on a list of allowed operations that can be applied to data. When you think about computation you might realize variables are there as placeholders for data, but that in a physical machine those placeholders hold something, perhaps a voltage that is random, or a voltage that signals all 0s. If we used Turing’s vision of a machine reading paper tape, that tape could have no marks on it. Blanks are still data. So in the concept of a machine there are really no variables at all. Just data of one sort or another. So if a machine is to take on the rule of evaluation functions and it has no variables, then mathematics and computation ought to be describable without variables as well. Such a description of functions is as combinators but most people today will know them as gates and these are the gateway between Software and Hardware. We can explore this with some examples.

Gates and Combinators

In the Konstants restaraunts, \(K\) is the combinator. When followed by two pieces of data (which can be grouped in parentheses) it yields the first of the two ignoring the second.

  • K "Curry" "Fries" yields "Curry".
  • K 3 7 yields 3.
  • K (3 7) 5 yields 3 7. The parentheses around (3 7) forced us to treat that as one piece of data and so it was the first of the two pieces and thus returned.
  • Working from the outside in, K (K 3 7) 5 yields K 3 7 (the first term to the outermost \(K\)) which in turn yields 3.
  • Now working from the inside-out, K (K 3 7) 5 yields K 3 5 (the second \(K\) was applied first to 3 7) which still yields 3.

Viewed form the perspective of the second term, this is a constant function.

The identity combinator I is defined by I x yields x. It simply returns its argument unchanged.

It is worth acknowledging that we are using variables, \(x\), to talk about a system that avoids variables! Well to that we can remark two things. First the use of variables here has no concept of scope, free/bound, local/global. These are variables in their simplest “fill-in-the-blank” form we always felt was logical. Secondly, we can if we want simply use words to avoid the concept of variables. Instead of I x yields x we can say “A machine that outputs whatever it is given.” Brevity and history are the sole reasons to revert to variable language.

Emergent logic

The game now is to list a number of combinators that can assist you in building a program. It may surprise you to learn how powerful K together with I can be. For example, the next exercise asks you to confirm that combining K and I is already enough to make a program that manages the concept of if a then b else c.

Let K be represent True and K I represent False (True and false are not something new, just names for K and K I). Next, define a new combinator IF by IF a b c = I a b c. Show that:

  • IF True 3 7 yields 3
  • IF False 3 7 yields 7

Because of this behavior, the IF combinator is usually called a conditional combinator and instead of IF a b c we write it:

if a then b else c

So far we chain together our combinators as lists, but once we make a clever little program like if-then-else we might want to compose it with other little programs without physically rewriting all the lines of instructions. We can do that with a combinator specially built to combine two programs into one and apply them in a specified order.

The \(S\) combinator (for Schonfinkle) is defined so that \(S~f~g~x\) yields \(f~x~(g~x)\). It allows us to apply a function to an argument and then apply another function to the same argument, combining the results.

S f g x yields f x (g x).
S K K 3 yields K 3 (K 3) which in turn yields K 3 3 which finally yields 3.

Set B to be S (K S) K. Show that B f g x yields f (g x). That is, B behaves like the composition combinator, it applies the program f to the output of the program g.

When you think of the operations of combinators like K, I, and S it may strike you as highly mechanical. That is the right picture to have. And perhaps you are also convinced that in combination they begin to make a tiny bit of sophistication, such as if-then-else, counting, possibly more. Well in fact they can do everything any computer can do.

A system \(\mathcal{A}\) of gates that has gates S, K, and I where for any gates f,g,h

  • K f g yields f
  • I f yields f
  • S f g is always defined
  • S f g h yields f h (g h) when either is defined.

is capable of carrying out any computation that could be described by substitution of variables. In other words it is a universal computing system, what we call Turing Complete.

Notice the complete absence of substitution and variables so the trapped variable problem just does not exist in computations. Gone also is the requirement that we are secretly depending on infinity to get substitution to work. It was only ever a mistake in vague mathematics and the programming languages used to bridge humans to machines. Put another way, humans who can imagine a place for infinity are beyond what a machine can imagine for itself.

\(S~K~K~x\) yields \(x\). In this sense \(S~K~K\) behaves like the identity combinator \(I\).

Applied Combinators and modern hardware

Unfortunately it is not the case that using just these three combinators S, K, and I is a fast way to write practical programs. For example we saw we do not really need I because we can get the same behavior as S K K. But doing three operations instead of one is silly. Modern day CPUs therefore boast over a thousand additional instructions (called applied combinators) and GPUs use a few hundred each designed to better use the time and energy we have to achieve a computation.

As another exercise you can invent counting, additions, binary numbers, decimal numbers and on and on. But those will be very slow. Instead you are better off adding many more combinators to your list to give yourself a solid start.

In the Intel x86 instruction set there is a command to add two numbers. ADD. It takes the next to terms and adds them.

  • ADD 3 7 yields 10.
  • Working from the inside-out, ADD (ADD 3 7) 5 yields ADD 10 5 which in turn yields 15.
  • Working from the outside in, ADD (ADD 3 7) 5 gets stuck! Based on work from the outside we have not yet computed ADD 3 7 and so the outside ADD is stuck waiting on that number before it can continue.

Notice how the ADD operation is not as straight-forward as the K and I or even the IF combinator in that ADD really only makes sense when followed by numbers. This is why it got stuck when working outside-in instead of inside-out. It is striking that something as basic as adding can run into trouble based purely on how we ask the question. To get unstuck we would need to go into the design of the hardware and rewrite the order of operations. This highlights the difference between pure combinators like \(K\) and applied combinators like ADD. This is what is known as an “Applied Combinator”.

A fixed-point combinator \(F\) is one where \(F~g\) yields \(g~(F~g)\). We call this a fixed-point because \(g\) applied to \(F~g\) yields the same result as \(F~g\) itself, so the “point” \(F~g\) is fixed. When introduced as an option for computation they give the programmer a way to have an operation applied to itself repeatedly in a process known as recursion. That is an essential power in modern programming so the ability to create such a combinator (or gate) is highly valuable. The mathematician Alanzo Church (1903-1995) found one such operator he called \(Y\) and Alan Turing (1912-1954) discovered another called \(\Theta\).

There is a tech incubator launched in 2005 called the “Y Combinator” which also hosts “Hacker News”, a website dedicated to articles and announcements on cutting edge technology.

Higher Computing Models

Many readers stop at “Turing Complete” and missunderstand this to mean every computer, given enough time and energy, can do all computations. This is misleading. Think of the job of a sound amplifier. Sounds waves are analog signals which means they use decimal numbers like \(\pi/4\) and \(\sqrt{2}/2\) which are both numbers that use an infinite number of decimal places. The amplifier does not seem to care. It takes in the signal and makes a new signal (also of infinite decimal places) that is louder. It is not possible to explain this simple task using finite strings and substitution rules on a Turing Machine. And yet, clearly sound amplifiers perform their operations without trouble.

It is not only discrete versus analog that seems to separate levels of computing. Increasingly studies of brains and neural networks in cognitive science suggest to researchers that thinking in liveing organisms is not well described by Turing Machines. The subject of realizibility now explores that frontier. If that were not enough, not long after Turing’s work, the mathematician/logician Kleene discovered mathematical consequences that force their to be more computing models beyond what Turing had imagined. While it might have been guessed that Kleene’s higher computing models would also be interchangeable like Turing’s, that turned out to be false. When it comes to computing in its full generality, there really isn’t one computer to rule them all. It is only the most basic level of computing that is interchangeable.

NoteKleene’s need for higher computing

Kleene’s goal was to explain how it is possible to have a claim such as

Proposition P: “There exists a number with some a fixed property.”

where \(P\) is true but doesn’t have a proof. That may sound impossible. Obviously if you have specific value \(c\) that works, then you just have the you, or a computer, return \(c\) as evidence for that property. It seemed that was the only way for such a proposition to be true. However, years earlier a mathemitician Hilbert had made a lot of claims about points existing in geometry that seemed to give no process to explaining what the point even was. And a few years later, the mathematician/logician Godel had shown that in any sufficiently robust theory (such as natural numbers, what we call “PA” for Peano Arithmetic) there are some properties \(P\) which are true but are impossible to prove. Put together in the right way this mean there are some claims of the form “there exists a number \(x\) with property \(P\)” that are true but have knowable value \(c\) for which \(P(c)\) holds. Weird for sure, but lets not follow that tangent.

What Kleene realized is that a proof is just a computation (back to our Curry-Howard-Lambek correspondence). And there is a way to turn anything that is true but not provable into something provable by moving to a more specific logic, “Con(PA)” in the case of natural numbers. So knowing that there is a logic that can prove the previously unprovable claim, there should be a computing model that can compute it. So Kleene built it.

Note, once you build a more specific logic like Con(PA) there will be new Godel exceptions that are true but not provable. So you will need a Con(Con(PA)), and so on. Likewise we get larger and larger models of computing.

A remarkable consequence of Kleene’s effort was the ability to produce a picture of undecideable problems. Through the work of Mandelbrot who invented fractals, nobel laurate Penrose who studied them, and the mathematicians Dude, and Braverman-Yampolsky were able to show that the whether or not a point lies in Julia set (the fractal below) is undecidable in a decimal number computing system. The ability to photograph what we don’t know is to this author far more remarkable than Event Horizon’s photographs of black holes. Bring the topic up with your friends in physics and write to me about how that interaction goes.

Applicative structures

Let us think of a computation as a collection of gates \(\mathcal{A}\), which can includes constants such as a gate the sets a voltage to 0, or a gate that sets a voltage to 1. A computation is to have some gate \(x\) applies to some get \(y\), \[ x\cdot y \text{ means apply gate $x$ to gate $y$} \] For example, I 0 yields 0 and K 1 0, understood as (K 1) 0, yields 1.

, or a gate that adds two voltages together. We can also include combinators like \(S\), \(K\), and \(I\). The collection of all such gates is called a universal computing tower. A universal computing tower is a collection of gates that can be combined to perform any computation that can be described by substitution of variables. In other words, it is a universal computing system, what we call Turing Complete.

What we have actually said is that a computer that takes in a string of finite tokens and applies rules of substitutions is no different to providing gates S, K, and I. There however many examples of analog computing: decimal numbers inputs (which may have infinitely many decimal places) output other decimal numbers. Think of an amplifier on a sound system which takes in sound waves, makes them louder by altering the amplitude, and returns a new wave. There are also studies of neural networks and brains in cognitive science that do not sit comfortably in the Turing computational model because of a similar context where it is best to think of infinite sequences of data being modified to infinite sequences of output.

NoteDeflating infinity

A reader like my younger self might point out that sound waves are moving a finite number of air molecules and thus are ultimately discrete finite problems. Therefore Turing computation is ultimately enough. My older wiser self would now answer that this misses the point.

An analog computer (like an amplifier) can be built from a few gates (some gears or a few electronic parts). Meanwhile, a model of all the air molecules in a concert venue is so vast and chaotic that it would take a computer simulation with roughly as many transistors as air molecules to run. Such a system could never be built or even properly analyzed in theory. Even a digital amplifier will ultimately transfer the process from software to some devices that moves a speaker diaphragm as bulk analog instrument to move the quintillion-trillion molecules of air in a stadium. So the model of 2nd, and higher order computation is meant to capture the reality that we will need to explore and control computations that are not practically described as Turing machines.

Scientist call these sort of separation of models “emergence” where the behavior at some scale becomes so much better explained by a simple model that return to its constituent parts is not useful. A theory that works at different scales is called a Gauge Theory, from the term for trains that work on differently spaced tracks. Computation is a Gauge theory, and Turing Complete computation is the lowest scale of this gauge.

Summary

  • Combinators are operations that can be applied to data.
  • The \(K\) combinator is a constant function that returns its first argument.
  • The \(I\) combinator is the identity function that returns its argument unchanged.
  • The \(S\) combinator allows for the application of two functions to the same argument and combines the results.
  • The \(B\) combinator behaves like function composition, applying one function to the output of another.
  • The S, K, I combinators together are sufficient for universal computation.
  • Applied combinators, like ADD, can be more efficient for specific tasks but may have limitations based on their context.
  • Fixed-point combinators enable recursion by allowing a function to be applied to itself.
