30  Probabilistic Data Types

We have seen that many useful data types emerge when we think of an associated logical construct. Abductive reasoning and especially the precise form found in probability continue this trend. We will look closely at one of the first in a long line of probabilistic data structure.

NoteFast Membership Test Problem

We need to scan a large amount of data ()but quickly recall if we have seen that data (x) before, i.e. test if (x).

You have a web browser that needs to prevent users from accidentally accessing a malicious website. The browser maker receives updates of the nearly 10,000 a day new threats and it adds it to 1-2 billion threats already known. If it was to simply list the URL that would take many gigabytes to store and to search which is way too slow for use. If instead it could simply be notified quickly that a specific link was on the “naughty list” it would be enough for the browser to issue a warning to the user.

You have a router that connects clients to various services. Somewhat often a connection gets dropped without warning. Then the user reconnects and you would like the router not to start them over with new session but instead reconnect them with their application in process. It takes work to link users with dropped connections so you can only afford to search for the link if you are certain this is a returning user and not a new user. If you could quickly check you bank of returning users it would let you know if you should spend the time.

30.1 The Strategy: Accept some False Positives

Burton Bloom’s strategy assumes one extra detail not in the original problem. He assumed:

SOME FALSE POSITIVES ACCEPTED It is acceptable if in a small number of cases we may claim (x) when in fact it is not.

The justification for this extra claim is that many example that need the FAST MEMBERSHIP TEST PROBLEM can handle this outcome. For instance, the malicous website example it is ok of we warn a user of a website that is actually safe. They can override our warning. As long as this happens rarely the user will likely find it acceptable. Likewise with identifying repeat connections, if a small number trigger a search that will fail, it is only a small number of times this extra work occurs.

30.2 Bloom’s Filters

With a small number of false positives accepted, Bloom’s solution can be summarized with what today are known asBloom Filters(because they filter the data). While the data structure is called a “filter” it will help us to introduce it in the language of sets ().

Bloom FiltersFrepresent a set ()with exactly three possible operations.

  • Resetremove all elements form ()(we say reset/clear the filterF)
  • InsertAdd an element (x) to ()(we say insertxintoF)
  • QueryTest if an element (x) ismost likelyin ()(we say query ifxis probably inF).

Remark.Technical experts prefer to state “query” as testing that (x) because this test is always correct.

A Diagram of the Operation Semantics.

Clearing the filter

The filterFis technically nothing more than a string of true or false values (usually recorded as 1’s and 0’s calledbits(binary digits).). This comes in various size such as 8 bits, 16 bits, 32 bits, 64 bits, 128 bits etc. because those numbers match much of the hardware available. But we will illustrate with a small list of just 4 bits.

To “clear the filter” means to set set all the values to false. F=[false, false, false, false]

Inserting an element to the filter.

Bloom’s filter depends on a key ingredient known as a “hash”. This is a function that takes in data and assigns it a short nickname. Humans want names made of letters, but our computer will be happy with a nickname 1’s and 0’s, ortrueandfalseas we call them. So for example

Hash(www.virus-r-us.com) = [true, false, true, false]
Hash(www.fda.gov) = [true, false, false, false]
Hash(www.spam-mail.rog) = [true, true, false, false]

The nicknames are called “hashcodes”. The hashcodes should be the same size as the filter. Again for illustration we use 4 bits.

To “insert” a hash (h)in to the filter (f)means to scan every index and take the OR (OR) of the value in the has and the value in the filter.

(f_{new}[I] := f_{old}[I] h[I])

Example.Suppose thatf=[false, false, false, false]and the hash code weh=[true, true, false, false]then we get

f_new := f OR h
= [false OR true, false OR true, false OR false, false OR false]
f_new == [true, false, false, false]

Nowf_newreplacef, i.e.f:=f_new.

Example.Add another thatf=[true, false, false, false]and the hash code wej=[true, true, false, false]then we get the new

f=[true,true,false, false]

Notice the first true is actually a contribution form bothhandj. This is the crux of why this method will eventually allow some false positives. It happens rarely but it can.

Query

To query we do nearly the same operation but replace OR with AND.

(f_{new}[I] := f_{old}[I] h[I])

Example.Usingf_newfrom above, andhfrom above we want to confirm thatf_newcontainsh,

h_test == f AND h
= [true AND true, true AND false, false AND false, false AND false]
= [true, false, false, false]

Sinceh_test == hwe have our confirmation.

Example.Usingf_newfrom above, andk=[false, false, true, false]then the test fails:

k_test == f AND k
= [true AND false, true AND true, false AND false, false AND false]
= [false, false, false, false]

Sincek_test != kwe have our confirmation,khas not been added.

Example (A false positive)Usingf_newfrom above, andr=[true, true, false, false]then the test fails:

r_test == f AND r
= [true AND false, true AND true, false AND false, false AND false]
= [false, true, false, false]

Sincer_test != rwe have our confirmation,rhas identified as in the filter, but this is just a mistake where the filter got overfull and not been added.

Probability of Membership saying Yes

So how does a false positive occur? Lets begin by counting how many ways we get a positive query. Since we use AND we can go index by index.

  • hash(x) [i] == filter[i] AND hash(x) [i]

Now ifhash(x) [i] == falsethen the value offilter[i]can be true or false. So the actual test comes down to the places wherehash(x) [i]==true. In that case we require thatfilter[i]==true.

Facthash(x)is in the filter if every indexifor whichhash(x) [i]==truethenfilter[i]==true.

ConsequenceThe number of hashes in a filter is (2^k)where (k)is the number of true values in the filter.

False Positives The number of false positive is (2^{k}-v) where (v) is the number of intended values. The probability of a false positive is \[\frac{2^k-v}{2^d}\leq \frac{1}{2^{d-k}}\]where (d) is the total number of bits. So if (k<d)we have a fraction of false positives.

Remark.In a full Bloom filter uses a mix of hash functions and multiple filters to cross-check against false positives and make for smaller filters storing even more data.

16-bit Bloom filter (single hash) example

Use one hash function that maps a string to a sparse 16-bit code (exactly two 1-bits):

H(s) = (1 << (sum(bytes(s)) mod 16))
OR (1 << ((sum(bytes(s)) + 7) mod 16))

Start with an empty 16-bit filter:

F = 0000000000000000

Insert 12 sample website strings with their sparse 16-bit hash outputs (binary and hex):

1.  bad-login.biz         -> 0000000000000011  (0x0003)
2.  free-prize-now.co     -> 0000000000000110  (0x0006)
3.  update-wallet.app     -> 0000000000001100  (0x000C)
4.  urgent-alert.cc       -> 0000000000011000  (0x0018)
5.  verify-account.link   -> 0000000000110000  (0x0030)
6.  reset-password.run    -> 0000000001100000  (0x0060)
7.  gift-card-win.xyz     -> 0000000011000000  (0x00C0)
8.  support-ticket.help   -> 0000000110000000  (0x0180)
9.  promo-claim.click     -> 0000001100000000  (0x0300)
10. security-check-now.top-> 0000011000000000  (0x0600)
11. login-confirm-now.site-> 0000000000110000  (0x0030)
12. invoice-fix-fast.pro  -> 0000001100000000  (0x0300)

Final filter after all 12 inserts:

F = 0000011111111111  (0x07FF)

Size comparison summary

If we estimate each URL at about 100 bytes, then storing 12 full websites takes:

12×100×8=9600 bits

The Bloom filter above uses only 16 bits, so the storage ratio is:

960016=600

So this example filter is about 600 times smaller than storing the full 12 URLs directly.
