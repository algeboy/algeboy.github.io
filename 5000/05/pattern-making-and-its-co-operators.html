22  Week 6 Day 2 Pattern Making & its Co-operators

Day 2-3: Pattern Making and its Co-operators

The life of a file.

One day Dada created a file. She named the file "Top-Secret-Read-Immediately.txt" and started typing out a story, each line adding to the story so that file grew. Almost as quick as things started, the story was over. Dada transmitted the straight to Codaydeh.

Codaydeh immediately opened the file and started to scroll, each line appearing one after other. The story was amazing! What a mystery, what would happen next? Codaydeh scrolled further but nothing happened! The file just stopped, mid sentence. There was nothing more there. This couldn’t be right? Had some of the file been cut off in transmission? Or was Dada suddenly interrupted?

Pattern Matching

The allegory of sending a file is an archetype of a form of reasoning we all face in everyday life but which presents several challenges to computation. While we would like to think of the file as one piece of data, its creation and its uses are spread apart, often separated by time and space. The separation means that the data will need a number of intermediate uses. We have already seen how we make a data type that breaks down into parts, an “Inductive Type”. This is like the letter writer Dada. There are prescribe number of ways to make the data (introduction rules)

(1: A^{d_1}A) (2: A^{d_2}A),…, (m: A^{d_m}A)

We can shorten this one one function

(: A^{d_1}A^{d_2}A^{d_m}A)

There is only one way to use this data: match each pattern of introduction (construction) and give each of those a role.

There is only one elimination rule (use) for the packaged data and it is determined by identifying the uses of the individual means to package the data. Need a little more review? Go through the lab 6 slides here.

Pattern Making

Now let’s take the perspective of the letter reader. When Codaydeh receives a transmission he knew just what to do and starts taking in line by line text. There is only once source of the data but many uses. The data could be broken into words, then characters, those could be printed in some font, shown an a screen, saved to a file, who knows. But we don’t need to know the use to know the work is to take this single source and divide it up into parts we can use. That means we can focus on the many elimination rules but need only one introduction rule. The trick is to reverse the semantics, all arrows go the opposite direction. Let us start by reversing the operators.

Co-operators of Co-induction

Suppose we expect that our algebra packaged data up using operators (^{d_1}^{d_n}). Then when we get a data from () then we should expect it was made from one of the terms (^{d_i}). So we just need to reverse this. That is, we need a function (^{d_1}^{d_2}). How do we make it? Let make (n=2) to keep things easy.

Step 1. Remember that (^{d_1}^{d_2}) is type based on OR, and so it has 2 introduction rules, one for (_1:^{d_1}^{d_1}^{d_2}) and (_2:^{d_2}^{d_1}^{d_2}).

Step 2. We need to test the incoming (u:) to know if it came from the left (^{d_1}) or right (^{d_2}). Whichever one it is we can make a function (^{d_1}) or (^{d_2}) and then compose it with (_1) or (_2).

The point is we can get form () to (^{d_1}^{d_2}).

Now the precise mechanics to allow this is subtle and requires the programming language called “destructors” or “unapply”. In particular there is not function (^{d_1}) because not every input comes from that side. We test to be sure but it means that this side of our program is technically not “tapeable function”. So there is a special process within the logic that lets us use this as “partial function”. You can ignore this, but it feels right to tell you that sometimes logic needs to go deeper.

Fortunately most modern programming languages include some nice notation to hide the mechanics and make it easy to use. Here’s a program that hides the work. We have a file that can have an End Of File (EOF) or we can have a character a:Char and a file tail:File and we want to add a to the file at position p. This would formally be the following function type.

(: ^0) and ((a,p) : ^1)

which means when unified as a single operator we have

(displaystyle : (^0{a:} {p:} ^1))

Thus the co-operators will reverse this array

(displaystyle : (^0{a:} {p:} ^1))

Let’s call this co-operator unpack and see how close we can get with software.

OCaml Example

type file =
| EOF
| Insert of char * int * file

let unpack (f : file) : (file array, (char * int) * file array) Either.t =
match f with
| EOF -> Either.Left [||]
| Insert (c, p, rest) -> Either.Right ((c, p), [|rest|])

This approach shows the two possible returns, a File array, or a file array indexed by a character and a position. However it falls short in that it does not have the lengths of these arrays which are in fact known to us. We can achieve this by removing the array type and using the specific number.

Scala Example

enum File:
case EOF
case Insert(c: Char, p: Int, rest: File)

def unpack(f: File): Either[Array[File], ((Char, Int), Array[File])] =
f match
case File.EOF => Left(Array.empty[File])
case File.Insert(c, p, rest) => Right(((c, p), Array(rest)))

Java Example

import java.util.Optional;

sealed interface File permits File.EOF, File.Insert {
record EOF() implements File {}
record Insert(char c, int p, File rest) implements File {}
}

class FileUnpack {
static Object unpack(File f) {
return switch (f) {
case File.EOF eof -> eof;
case File.Insert ins -> new CharFilePair(ins.c(), ins.p(), ins.rest());
};
}

record CharFilePair(char c, int p, File rest) {}
}

Agda Example

open import Data.Char
open import Data.Nat
open import Data.Sum using (_⊎_; inj₁; inj₂)
open import Data.Product using (_×_; _,_)

data File : Set where
EOF    : File
Insert : Char → ℕ → File → File

unpack : File → File ⊎ ((Char × ℕ) × File)
unpack EOF = inj₁ EOF
unpack (Insert c p rest) = inj₂ ((c , p), rest)

Co-recurse: the unique introduction rule.

Now that we have seen how to unpack operators with co-operators we now need to link them to other co-operators. We continue to reverse the picture.

We can use this to convert our file into glyphs and display it on a screen. We can also use it to convert JSON into a screen image or convert to another format like HTTP or UPD to transmit it through the internet. The game keeps going.
