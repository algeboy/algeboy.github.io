The problem

At this point we know how types of data separate context, but the real goal is to have different context talk to one another. For example, suppose we have people in one context (X) and shoes in another context (Y). That is obviously not much of a story. But now suppose we link them by the function “buy” where each person in (X) buys a shoe from (Y). That relationship lets us image a cascade of computational questions.

  1. What shoe models are selling?
  2. Does the sold inventory should match exactly the sales receipts?
  3. Does every client get helped by at most one employee?

These questions still have a veneer of business language. How can a computer be asked to solve things that are not about true/false and numbers?

Making Equations

Beyond having a function (f:XY), our computers need equations they can solve.

  1. X=Clients, Y=Shoes, and (f:XY) is shopping. Then for which (yY) does (y=f(x)) have at least one solution (xX)?
  2. X=Shoes, Y=Receipts, and (f:XY) inventory. Does each (yY) have exactly one solution (xX) with (y=f(x))?
  3. X=Employees, Y=Clients. Now (f:XY) assigns the employee to a client. We want to ask if (f(x)=f()) does it follow that (x=)?

From here you can begin to imagine numerous ways to express questions that can be fundamentally treated as** solutions to equations** of the form

(y=f(x))

How do we solve equations? Algebra!

Think of how you solved equations in the past.

(x+4=2)? Add -4 to both side to get (x +4-4=2-2) so that (x=-2).

Well solving equations (y=f(x)) for an arbitrary function can be approached in somewhat the same way. Not every function is easy to use but there are broad classes of function where the behavior of (y=f(x)) is predictable. What we do is study those functions and their properties closely. Then we make strategies to write the functions we have as a composition these easier families. Let us begin with the first case.

Surjective when Modes change

When we write functions for computations they often behave in ways that change based on the situation. And it can be frustrating to learn terms like “surjective” only to find we cannot convincingly use this term about computer programs. Yet the situation is not that bad. Often what we mean is to ask the question in “modal logic” where we consider possible worlds (also called “states”). So let’s inspect this situation.

Assigning tasks when there are too many workers

Let def assign( t : Task ) : Thread be a function that assigns a given task to a thread (a computer unit). Threads are assigned to work on a schedule, which is a function def schedule( th : Thread ) : Time. Schedules change, so there can be several schedule functions def schedule1( th : Thread ) : Time, def schedule2( th : Thread ) : Time, and so on, for example

schedule1( thread1 ) = 1``schedule2( thread1 ) = 1

schedule1( thread2 ) = 2``schedule2( thread2 ) = 2

schedule1( thread3 ) = 3``schedule2( thread3 ) = 4

schedule1( thread4 ) = 4``schedule2( thread4 ) = 3

What happens if we only have 2 tasks and these are assigned to thread1 and thread2? In that case the schedules are functionally the same:

schedule1( assign( t ) ) == schedule2( assign( t ) )

That is, because the only differences in schedule are in thread3 and thread4 we don’t notice the difference in schedule. And yet schedule1 != schedule2. This is an illustration that for such few tasks, assign is non-surjective.

Assigning tasks with too few workers

Fast-forward to having 7 tasks and we need to use all the threads we can. Now assign includes tasks assigned to thread3 and thread4. Therefore

schedule1( assign( t ) ) != schedule2( assign( t ) )

The only pair of schedules that produces the exact same order of tasks in this case is to use the exact same schedule. Surjective assignment can be “reversed” on the right.

Modal Surjectivity

So in practice when we compute we often benefit from considering whether functions are surjective in all worlds

Necessarily surjective = ((uv, uf = vf u=v))

For example, def getWindow( hw : WindowHandle ) : Window outputs the window labeled hw. There is a handle for every window no matter what windows we have open. So this function is surjective in all possible worlds.

Meanwhile a function like scheduling can have worlds where it is surjective but perhaps not every world.

Possibly surjective = ((uv, uf = vf u=v))
