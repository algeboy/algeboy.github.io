Week 7

Day 1 Relations and Orders

We saw with deduction that one of the ways to build a new data type is to modify what we mean by “equals”. In programs we override equality. But you are likely familiar with other ways we relate data. For example, some numbers are large, others are small, that means (xy). Likewise some expressions in reasoning benefit from organization.

General Relations

To turn data like 541 or a PDF into a value we can judge we need to create a relation. Here are some samples relations.

  • P(541) = “541 is positive”. Something we can judge, and we judge it is true.
  • P(541) = “541 is even.” Something we can also judge, but this time we judge it is false.
  • Q(MyCV.pdf) = “MyCV.pdf has page numbers.” Something we can judge. Is it true? We’d have to read the file to find out.

Propositions

A Proposition is a sentence we can claim and judge. The outcome depends on our mode. Recall from Week 1 we have three forms of propositions

  • () for Theory is generally True () and False ()
  • () for Computation is generally True () and False () but must be supported by evidence so it may not come to an end if the evidence never comes.
  • () for Practice is generally True (), False () along with a host of gray are, perhaps Maybe, or Unknown, or Likely, Unlikely, etc. We will here simplify and just allow a single third value +.

Relations

So what is a Relation? First choose the appropriate proposition category (Theory, Computation, or Practice). Then a Relation is a function form lists of types (X_1, X_2,, X_n) into (). That is

(P:X_1X_n)

  • P(x) = “x is positive”. This is not something we can judge yet, but as soon as we replace the variable by a value we will be able to judge it. In fact this sort of claim is simply true of false, Theory proposition applies.. So this is a function from data into propositions but it only makes sense when given decimal numbers (). It is a Relation (P:{,})
  • P(x,y) = “x +y =0”. This is a either true or false, so we can judge this once given decimal numbers of x and y so this is a relation (P:{,})
  • Q(x) = “x has page numbers”. Here x is a file, so File is our input type. However, the concept of “has page number” is clear for documents but it means nothing for images, videos and so many other documents. This suggests a practical proposition of Prop={true, false, undefined}. This is a relation (Q: -> {}). In common software syntax this might be def hasPageNumbers(x : File) : Option[Boolean]. The Option wrapper allows us to give back a value of True/False when it makes sense, or nothing when the input file is not a document.

General Relation Vocabulary

  • Valence or Arity is the number of inputs to a relation. E.g. P(x), Q(x) are valence 1, also called unary. P(x,y) is binary, valence 2.
  • Homogeneous: a relation (R:X_1X_n) where for each (i,j), (X_i=X_j). In this case we often write (R:X^n).
  • Heterogenous: a relation that may not be homogeneous. In general a homogeneous relation is also heterogenous but not the other way around.

Mathematical Conventions

Mathematics tends to study relations (R:X_1X_n) more fully than other subjects and much of mathematics is in the Theory camp of reasoning. Because of this most of mathematics sees relations as just true and false. When this is the case then it is enough to know just the values which are true.

({(x_1,, x_n)X_1X_n R(x_1,, x_n) })

Because of this, much of mathematics will define relations not by a function but by a subset, that is, mathematics will often write

(RX_1X_n)

Even if this is bit short cited on the part of mathematicians not to consider the nuance of relations in computation and in practice, it is still a notation used broadly and you can introduce that notation meaning in fact (R:X_1X_n). Just add that clarity to your discussion in text.

Binary Homogeneous Relations

Amongst the most used relations are binary homogeneous relations

(R:XX)

In this case we generally prefer an infix notation. Example, instead of (R(x,y)) we choose some symbol, maybe = or < or == etc. and write things like

(x=y), (x<y), x==y, x!=y, (xy)

Since we need to keep talking about many binary homogeneous relations we will continue to use R as a generic name

(xRy)

Reflexive law

A binary homogeneous relation (R:X^2) is called reflexive if

(x.(xRx))

  • In number equality is reflexive (x=x), less than is not reflexive (5<5) is false, but less-than or equal is reflexive (xx)
  • In programming if one data type B extends another A it means every method for A is a method for B as well, though B may have further methods. Under this definition A has all the methods that A has so A extends A. However, in writing a program you may not be allowed to write A extends A as that leads the programming language to get confused with circular reasoning. This is a difference in definitions, so even experts can disagree on this one with good reason.
  • A daughter inherits traits from her father, but a daughter does not inherit traits from herself. So inheritence is not generally reflexive.

Reflexive Closure

In some situations it is convenient to assume a relation is reflexive even if it is not. Think of promoting (x<y) into (xy). This literally means

(xy := (x=x) (x<y))

We can do this to absolutely any binary homogeneous relation (R:X^2)

(xy := (x=x) (x<y))

The resulting relation (R^=) is called the reflexive closure. The notation we usually use is to add part of the equal sign to the original symbol. Here are some examples

  • (< )
  • ()

In other situations we want to remove reflexivity. We can do this as well.

(xy := (xx) (xy))

The notation similarly strikes out the equal portion.

Transitive Law

So what makes something an order? While humans make the rules, and thus can change them, by far the most popular definitions agree on one rule, the transitive law.

( (a < b )(b< c) (a< c))

Symmetric and Anti-symmetric laws

Two further relations laws are commonly encountered.

  • Symmetric: (xRy yR x)
  • Anti-symmetric: (xRy yRx x=y)

As we have seen there is a notion of “closure” for each of these. We simply force a relation to be symmetric. However, the closure for anti-symmetric is more sublte because it is forced to change the notion of equality. So this creates what we early called a partition.

Special Relations

Now mostly because of the popular use there are a bunch of combinations of these four rules that get names and you might be expected to know them in your future so we lets give them here.

Equivalence relation

Definition. A homogeneous binary relation (R:X^2) is called an equivalence relation if it is reflexive, transitive, and symmetric.

Equivalence relations usually uses language like this

(x=y), (xy), (xy), x==y, x.equals(y), equals(x,y)

You may also here the words “congruent” or “equivalent” or “isomorphic” as synonyms to equivalence relations. As always, it is ok to ask someone to explain their terms if you are not sure what they mean. And if you use a term, be able to explain it yourself.

Order relations

Definition. A homogeneous binary relation (R:X^2) is called an order relation if it is transitive. It is furthermore

  • A pre order if it is transitive and reflexive
  • A partial order if it is transitive, reflexive, and anti-symmetric.
  • A total order if it is transitive, reflexive, anti-symmetric, and for every (x,yX), (xRy) or (yRx).

There are many traditional order languages but some common ones include

(x< y), (xy), (xy), (xy)
