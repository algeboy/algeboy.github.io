6  Context

The differences between how a program reads \([1,2,3]+[4,5,6]\) or how games are played need to be given somehow otherwise we cannot agree on answers. We call this context. Context comes in two flavor:

  • Explicit context: declared rules and symbols often thought as important extensions of common knowledge.
  • Implicit context: context that is provided by experience, training, physical limitation, equipment, brands, common sense, social agreements, and other undeclared assumptions.

To continue the game analogy, most board games will need to instruct the player how to make moves left or right, forward or back, on the board. Those will be explicit rules. However, because gravity makes it impossible leave a piece above the board instructions wont typically make any effort to explain movements as up or down letting those be understood as implicit context. If there is to be an exception to that rule, for example, if a checkers game allows a piece to jump over another piece, then that knowledge is best made explicit because it is an exception to the usual.

In scientific work we often give context in words or we invent a short symbol to abbreviate the context in the future.

  • In the natural numbers, here after denoted \(\mathbb{N}\) we know \(5+8=13\). In this case the natural numbers was made as an explicit context clue, but + and even the meaning of decimals was left as implicit.
  • \(5\) o-clock plus \(8\) hours is \(1\) o’clock. While the operation is \(5+8=13\), the implicit clues of time hinted that we should evolve this to a 12 hour clock and return the answer as 1.

The thermometer read \(350^{\circ} F\) but the recipe called for \(200^{\circ} C\). In this context what are \(F\) and \(C\) and what is \(\circ\)?

NoteContext conventions

There are various names used instead of the word context. You might here “set”, “type”, “class” or “category”. First of all these are all forms of context. Secondly, they are context with added requirements which we will see in detail later. Thirdly, they each use a slightly different vocabulary which will help you fit in with the field. For example:

  • Data \(x\) “in” a set \(S\), denoted \(x\in S\).
  • “Instance of” a class, notation \(x\in C\) and x instanceof C in Java.
  • “Inhabitant” \(x\) of a type \(T\), denoted \(x:T\), x::T, and T x.
  • “Object” \(X\) in a category \(\mathcal{C}\), denoted \(X\in \text{Obj}(\mathcal{C})\) or as a node in a diagram:
 graph LR
   X-->Y

Some sciences add their own vocabularies such as “species in a genus/order/phylum/kingdom” or “chemicals in a family/series”.

You can see that it is the implicit context that causes us the most bother and opportunities for mistakes. But without it we would never get started as we would be for ever unwinding all the assumptions. Returning to the game analogy, sometimes it helps to start playing the game even without fully knowing the rules. That way situations can evolve that make it more obvious why we have a rule. If all we do is read the rules at the start it can be hard to appreciate what they mean and how to use them.

6.1 Explicit context in computing

In computing the implicit context can include such things as which operating system and hardware we use. Systems called package managers coordinate the delicate combinations of versions of software that must be used to make sure that updates to one system do not upset the working of another. In this book the programming samples have the name of the programming language in the lower right corner as a context, but we have left off discussion of specific versions and surrounding code used to run it. All that is critical but often done without our notice and clearly part of the implicit context.

Explicit context in programs is thankfully much easier to spot. Most programming languages introduce keywords such as
include, import, using, from

to declare explicit context. These are followed by names of other software described as “packages, libraries, modules” or other similar names. For instance:

using Probability

If you are using an Integrated Development Environment (IDE) then you will be given further support with the keywords changing colors or fonts and the system searching that the right information to be included.

Some software lets us personalize our logic by selecting new names, e.g.

import numpy as np

or including only a small portion of an otherwise large package like this:

from TensorFlow import Tensor

In the next example we switch to a software package called \(\LaTeX\) that makes fancy scientific fonts and images. That logic lets us personalize such things as what we want to name our colors.

\includepackage[dvipsnames]{xcolor}

The xcolor package loads a context for controlling colors and the option dvipsnames lets us choose a convention for color names what we prefer.

Even in mathematics you will find whims and personal conventions. Here are some common options authors choose for themselves.

  • The natural numbers \(\mathbb{N}\) include (or do not include) \(0\).
  • Coordinates (i.e. Vectors) are written as columns \(\displaystyle \begin{bmatrix} 1\\ 2 \end{bmatrix}\) with square brackets, or rows with parentheses \((1,2)\).

Symbols like *, _, and ... are known as wildcards and they typically signal that you are assuming everything from that package.

import java.awt.swing.*

Wildcards in science are often made in phrases like

We follow the notation of Halliday-Resnick-Walker (replace with the authors of your favorite reference book).

As a general rule be cautious about excessive use of wildcards. Asking a reader or even a computer to understand your specific intent from something as vast as a book or computer library can lead to confusion and incorrect assumptions.

A programmer has written the some code indicating context.

using LinearAlgebra
using Statistics
using CSV

A = random(900, 1000)
b = random(900)
x = A \ b

What are the explicit context clues? What are some items you might need to find in the implicit context?

6.2 Context in Practice

When dealing with practical situations, clients, data sets, or tools, your context might have to be something you create and include in your own way. This is often called “Meta Data”, “meta” meaning self-referential, so meta-data is data about data. Metadata adds helpful context and is often part of the specification of a file format but can also include optional documentation.

A meteorologist takes pictures of clouds in the same location over a period of decades. Some useful MetaData may include

  • Date and Time.
  • Location.
  • Image format.
  • Thumb nails.
  • Software versions.
  • Historical notes, such as “Fire in the area” or “system offline for maintenance”
  • Author and Copyright information. Along with being a good stewards of information, there are legal requirements to follow when using data so always include this information in your MetaData.

6.3 Context in Theory

Perhaps the biggest offenders of declaring context are those who work in “theory”. Part of this is because there may be years of training that makes the context familiar to those who work in the field. It is also often the case that working in theory means to change the context until we find the right conditions. So setting up clear context only to change them can seem a waste. However, the practice of being mindful of your context even in theory will prevent confusion. Each field sets aside conventions for dealing with context. These might be nuanced as requiring that everyone use the same notation, vocabulary, and take similar courses. So be on the lookout for your evolving sphere of theoretical implicit context, even in this course!

NoteContext names

When we want to discuss the role of context in an argument or program we cannot use a specific name or package because we want a place holder for all possible contexts. In mathematics the customary symbol for this is the Greek letter \(\Gamma\). In programs the abbreviation is often ctx instead. For example:

  • In the context \(\Gamma\) we have that …, but in the context \(\Delta\) we have instead …
  • import ctx1, ctx2 then compute…

6.4 Summary

  • Logic is sensitive to context.
  • Context can be explicit or implicit, and both provide the details necessary for proper judgment.
